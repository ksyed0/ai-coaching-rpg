# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once it has a first tagged release.

## [Unreleased]

Slice 1 proof of concept: text-only play from a terminal against AI-played NPCs (EPIC-0001, US-0001 to US-0012).

### Added

- pnpm/TypeScript monorepo with Vitest: `packages/events`, `packages/script`, `packages/adapters`, `services/runtime` (US-0001).
- Session event types and a pure state reducer; session state is always a projection of the event log (US-0002).
- Scenario package: YAML schema, loader and validator with cross-kind id uniqueness checks and warnings for injects past a scene's time box (US-0003).
- Scene state machine: exit evaluation, next scene, timed injects (US-0004).
- `ModelProvider` adapter with a scripted mock and an Anthropic implementation, a shared contract test suite, and `pnpm lint:sdk` to keep provider SDKs inside `packages/adapters` (US-0005).
- Session engine with an append-only JSONL event log, serialized operations, scene control and facilitator commands (US-0006).
- NPC agents with a cacheable persona prompt, a first-token timeout and an overall reply deadline, each falling back to the character's scripted line plus a facilitator alert (US-0007).
- Game Master that evaluates scene exit conditions with the model beside the conversation (US-0008).
- Session host and WebSocket server with per-role event filtering and role reconnect tokens (US-0009).
- Terminal client: `pnpm play` for players and the facilitator (US-0010).
- CI pipeline (`.github/workflows/ci.yml`): lint, tests with an 80% coverage gate, build, orchestrator validation, dependency audit, TruffleHog secret scan and CodeQL.
- Friday Escalation scenario (YAML) and an end-to-end simulation test that plays it through with the mock model (US-0011).
- One-command start (US-0012): `./run.sh` runs the server in Docker (non-root user, pinned Node 22 Alpine base, healthcheck, `.dockerignore` keeping `.env` and host `node_modules` out of the image, bind-mounted `data/`); `./run.sh --dev` runs it with `tsx watch`; `./run.sh --help` lists usage. `.env` is created from `.env.example` when missing.
- Session-log rotation on restart: an earlier `<id>.jsonl` is moved aside as `<id>.<timestamp>.jsonl` and never overwritten (US-0009).
- `pnpm demo --showcase` (US-0024): a longer scenario, `scenarios/friday-escalation-extended` (6 scenes, 3 players, 2 AI characters including a new CFO, `showcase.yaml` script with a validating loader), played in mock mode (CI) or `--live` with the real Game Master ending scenes; flags `--scenario`, `--max-lines`, `--max-fallbacks`, `--watchdog`; source-labelled narration, an AI contribution summary, a `showcase` JSON section, checks `S-01` to `S-12`, and an extra CI step.
- US-0024 review fixes: optional `expectSceneId` on the WebSocket `say` and `command` messages (refused as `stale_scene`, nothing appended; old clients unaffected) so the showcase can never skip or mis-place a scene; an optional `fallback: true` marker on the NPC fallback `utterance`; a final Game Master evaluation before the safety-net advance; a fifth transcript tag `[UNVERIFIED]` for AI lines seen through `--url`; checks `S-13` (no scene skipped) and `S-14` (mock scripts not exhausted); Markdown escaping of tag-shaped tokens, GitHub autolinks and `$`; symlink and `--json`-collision refusal for `--transcript`.
- US-0024 review fixes, round 2: the `expectSceneId` guard no longer reveals the current scene to a role outside it (`not_in_scene` first); the final Game Master evaluation is bound to its scene; `--transcript` writes with `O_NOFOLLOW`, refuses symlinked parents and compares the `--json` file by inode; invisible and look-alike characters can no longer fake a tag in a transcript; effort numbers in the extended scenario agree (full module 6 person-weeks, phased 3).
- Repeated AI character replies (US-0027): a cleaned reply equal (ignoring case, spacing and punctuation) to one of the character's own last 3 replies is asked for once more, inside the same reply deadline, with the extra system line "Your last reply was identical to an earlier one; say something new that moves the conversation forward"; a second identical reply is spoken with one warning alert (`character <id> repeated an earlier reply verbatim`).
- Player intent logging (US-0027): with `--players generated` the transcript and narration log each generated player's private intent (the scripted line it was asked to express) as a `[SYSTEM]` entry right before its line, the JSON `showcase.players.intents` lists them per slot and the summary counts them; they never reach the session log, a client or the Game Master. `--no-intents` hides them.
- Sampling temperature (US-0027): optional `temperature` on `ChatRequest`, sent by the Anthropic and OpenAI-compatible providers only when set; `NPC_TEMPERATURE` (0.8), `PLAYER_TEMPERATURE` (0.9) and `GM_TEMPERATURE` (0.2) are validated decimals from 0 to 2, documented in the README table and `.env.example`.
- Generated player output contract (US-0027): the private intent now sits in its own system section (no dialogue-like note for a model to imitate), the prompt demands only the spoken words, and a reply is cut at a separator (`***`, `---`, `___`, `===`) or a Note/Intent line before cleaning; AI character replies are cut at a standalone `***`/`---` separator followed by text.
- Repetition guard (US-0027): the AI character and generated player prompts say never to repeat or reword what was said and to move the conversation forward, and list the speaker's own last three lines.
- Generated player bots (US-0027): `pnpm demo --showcase --live --players generated` (optional `--player-model <id>`, default the NPC model) has the model speak the player roles too, so runs vary between scenes and runs. Each scripted line slot becomes a private intent in a prompt that holds only what that role may see (its brief and private facts, the scene, its injects, the conversation so far); the reply is cleaned like an AI character's, bounded by the server's line limit and sent through the ordinary `say`; a failed generation falls back to the scripted line (`[SCRIPTED]` plus a `player <role>: generation failed (...)` line). Lines are tagged `[GENERATED]` only when the model wrote them; the summary and the `showcase.players` JSON section count generated, fallback and verbatim-repeat lines apart from AI replies and Game Master verdicts, and check `S-15` audits the player prompts. Mock and CI runs are unchanged.

- `pnpm demo`: an unattended demo and test runner that plays the whole Friday Escalation with a facilitator bot and three player bots over real WebSockets and ends with a pass/fail checklist of 29 features (`--fast`, `--speed`, `--json <path|->`, `--live`, `--url ws://host:port`, `--session`, `--no-color`); exit code 0 when every executed check passed, 1 on a failure or the watchdog, 2 on a usage error. The default mode uses scripted mock models and a fake clock and is offline and deterministic; `--url` smoke-tests a running server such as the Docker container; a new non-required `Demo Run` CI job uploads the JSON report (US-0021).
- Retry of transient model errors (US-0022): the adapters classify failures with a typed `ModelProviderError` (`kind`, `transient`, `status`, `retryAfterMs`; sanitized message) for the OpenAI-compatible and Anthropic providers, and a `RetryingModelProvider` retries transient ones (HTTP 429/5xx/408, in-band overloaded or rate-limit errors, connection resets) before any text was yielded, with exponential backoff, jitter and `Retry-After`, inside the NPC first-token and reply deadlines. The runtime and the live demo wrap the NPC and Game Master providers; `MODEL_MAX_RETRIES` (0 to 5, default 2) and `MODEL_RETRY_BASE_MS` (100 to 10000, default 500) configure it. The mock provider can script typed errors.
- Reasoning-model support (US-0026): the OpenAI-compatible provider now notices `reasoning_content` / `reasoning` (streamed or in a JSON body). When a model spends its whole token budget thinking and returns no answer, the provider throws a retryable `ModelProviderError` of the new kind `reasoning_budget` instead of an empty reply; the thinking text is never shown as dialogue, never put in a message and never buffered. The facilitator alert and the demo narration then say "empty reply: reasoning budget exhausted". `NPC_MAX_TOKENS` (default 600, was a fixed 300) and `GM_MAX_TOKENS` (default 400, was a fixed 200) configure the budgets (whole numbers, 50 to 4000, validated at startup, also used by the live demo).
- US-0022 review fixes: Anthropic stream `overloaded_error` and other in-stream error events (raised by the SDK as a status-less connection error) are classified by their type; a custom Anthropic endpoint's connection failures (reset, refusal) are transient again and only a refused redirect is permanent; when the retry wrapper is used the Anthropic SDK's own retries are switched off per request (`sdkRetries: false`, so a call makes at most `1 + MODEL_MAX_RETRIES` requests); the Game Master's model call has a deadline of `max(NPC_REPLY_TIMEOUT_MS, 60 s)` (`gmDeadlineMs`); a 429 for an exhausted quota or billing limit is permanent; when a deadline cuts a retry short the alert reports the attempts made and the last error kind; the backoff cap grows with `MODEL_RETRY_BASE_MS` above 4 s.
- AI characters with distinct voices (US-0032): optional NPC role fields `seniority` (1 to 5), `responds_with`, `only_you_say` and `defer_to`; a `## Who else is in the room` and `## How you respond` section in the AI character prompt; a character may reply exactly `<silent/>` to stay silent (never shown or recorded, at most 2 turns in a row); AI characters reply junior first (ties by the scene's participant order; the last character of an unanswered round must speak, and a facilitator warning is raised if every character stays silent); a silent marker is recognised in any form (`<silent></silent>`, `<silence/>`, full-width or with invisible characters; `(silent)`, `*stays silent*`, `...` as a whole reply) and stripped before the reply is cleaned; roster lines tell a character how the others are tagged; optional `defers_text`; the showcase counts near-duplicate replies of two different AI characters to the same player line (token-set Jaccard >= 0.6, as `echoes / eligiblePairs`) and silent turns in its summary and the `--json` `showcase.voices` section (observations only). The scripted mock replies are per character, so the mock runs (29, 14, 15 checks) needed no change.
- Game Master reliability (US-0025): a tolerant parser that does not trust the reply (`<think>` blocks and code fences dropped; every complete JSON object is examined; a verdict must carry the random per-evaluation `"id"` nonce that only the system prompt holds, so an injected `{"verdict": true}` quoted by the model is ignored; disagreeing verdicts are `conflict`, an unclosed object is `truncated`, duplicate keys, arrays and unparseable objects give no verdict; a verdict given as the string `"true"`/`"false"` is read, `1`, `"yes"` and `null` never count; never throws), one bounded re-ask after a reply with no usable verdict (inside the same deadline; a model error or the deadline is not re-asked), and a new facilitator-only event `gm.no_verdict {sceneId, condition, reason, attempts}` (`reason`: `empty`, `no_json`, `bad_verdict`, `truncated`, `reasoning_only`, `conflict`, `no_nonce`) that replaces the free-text `GM: no usable verdict` info alert; `gm.decision` gains an optional `via` (`strict`, `tolerant`, `reask`). New settings `GM_TIMEOUT_MS` (500 to 600000; unset keeps `max(NPC_REPLY_TIMEOUT_MS, 60 s)`), `GM_REASK` (0 or 1, default 1), `GM_EVERY_N_UTTERANCES` (1 to 20, default 3) and `GM_TRACE_FILE` (off; raw Game Master replies, mode 0600), all validated at start-up with errors that name the variable.
- `pnpm gm-eval` (US-0025): an offline-first harness with labelled cases in `tests/gm-cases/` (each showcase scene in full is *met*, a cut before the agreement is a negative control *not met*, kept in step with `showcase.yaml` by a check), a corpus of raw replies for the parser, `--trace <file>` to replay a captured run through the current parser, `--build` to regenerate the cases and `--live [--runs n]` (by hand, never in CI) to measure a real model: usable-verdict rate, agreement, precision, recall, false exits on the negative controls, attempts and latency.
- Showcase (US-0025): `--gm-trace <file>` records every raw Game Master reply (owner-only file); the narration prints `[Game Master] no verdict for "..."` with its reason; the summary and the JSON `showcase.gm` add `noVerdicts`, `noVerdictByReason`, `reasks` and `via`; the mock script holds one fenced and one malformed-then-valid Game Master reply declared in `showcase.yaml` (`kind: tolerant`, `kind: malformed`) so `S-04` holds the run to them in CI; live runs get check `S-18` (scenes ended by the Game Master, early false exits, no-verdict rate by reason); `--min-gm-exits <n>` makes it fail below a threshold and `--max-false-exits <n>` (explicit only) fails it on early exits in scenes without AI characters.
- Facilitator token and abuse limits (US-0017): `FACILITATOR_TOKEN` (16 to 256 printable ASCII characters) makes `join_facilitator` require the token (SHA-256 digests compared with `timingSafeEqual`, never logged or echoed, a generic `unauthorized` and a 1008 close after the first failed attempt, more than 5 failures per address per minute block that address for a minute). New environment variables, all validated at startup with errors that name the variable and never show the token: `RUNTIME_HOST` (default `0.0.0.0`), `WS_MAX_CONNECTIONS` (32), `WS_MAX_CONNECTIONS_PER_IP` (8), `WS_MSG_RATE` (5/s), `WS_MSG_BURST` (20), `WS_JOIN_TIMEOUT_MS` (10000), `ALLOWED_ORIGINS` (none) and `TRUST_PROXY` (0); connection caps and the Origin check apply at the HTTP upgrade (503, 403, 429), each connection has its own rate limit, queue cap (64) and join timeout, and frames are capped at 16 KiB (was 64 KiB). The terminal client reads the token from `FACILITATOR_TOKEN`, `--token-file <path>` or a hidden prompt (there is no `--token` argument). `./run.sh` writes a random token into a new `.env` only. `pnpm demo --security` adds checks F-31 to F-33 (token, flood isolation, caps, Origin and join timeout) and `pnpm demo --url` passes `FACILITATOR_TOKEN` to a protected server. A refused connection stops processing (frames already queued or still arriving are discarded and the socket is terminated shortly after; the address is charged one extra failure per connection at most, only for a real `join_facilitator` frame, so a flood costs constant work), raw sockets per address are capped, the failed-login table is bounded, swept at most once a second and keyed by IPv6 /64 for global unicast addresses only, a raw socket over the cap gets a 503, `startServer` rejects an invalid token, the role id `facilitator` is reserved, an open server shows a note to the facilitator, the token file is read with a 1 KiB cap, the client warns before sending a token over plain `ws://` to another machine, an empty real-env token no longer overrides `.env`, `TRUST_PROXY=1` on a non-loopback host warns, and `run.sh` builds the new `.env` privately (it never writes through a symlinked `.env`; `.env.*` is git-ignored except `.env.example`; its token check agrees with Node's `.env` parser, including `export` and spaces around `=`). New `docs/THREAT_MODEL.md` (also the README limitation) says exactly what the token does and does not protect.

- Resume after a restart (US-0018): by default (`SESSION_START=resume`) a server that starts on the log of a session that was still running rebuilds it from the log through the pure reducer and comes back **paused**; the facilitator gets an alert with the downtime and types `/resume`. The downtime counts as paused time, so the scene's time box and its timed injects continue where they were and nothing overdue fires on `/resume`. A player line whose AI reply was lost in the crash is answered once after `/resume`; the Game Master continues from its last recorded decision. Participants rejoin and claim their roles again (with their join codes since US-0033) and receive their visible transcript (reconnect tokens are not persisted). An ended session's log is moved aside and a fresh session starts. `SESSION_START=fresh` (`./run.sh --fresh`) always moves the old log aside, as before.
- Session log format 1 (US-0018): `session.started` records `logFormat` and the scenario's SHA-256 (`scenarioHash`); a new `session.resumed` event marks a restart (players see "session paused (server restarted)"). A restart refuses, with a message naming `SESSION_START=fresh` and without touching the log, a log corrupt beyond a cut-off last line (a seq gap, duplicate or reordering, another session's event, an unknown event type, a malformed middle line), a log of a newer format, a log of another scenario (the SHA-256 is of the scenario as loaded and validated, so an app upgrade that changes how a scenario loads can also refuse an in-progress resume: use `SESSION_START=fresh`), or a log or lock with extra hard links or another owner; a data directory that stays writable by others is refused too. A crash between the events of one operation (a scene exit and the next scene, an inject and its effect, a start, an opening inject) is completed on restart and noted in the alert. A clock that went backwards across the restart is reported (the downtime is then counted as 0 s). Logs without the field (format 0) are resumed on a matching scenario id and version.
- One server per session log (US-0018): `data/sessions/<id>.lock` (exclusive create, no symlinks, mode `0600`) with a 5 s heartbeat; a second server is refused; a lock left by a crash is taken over at once when it names this host and a dead process (or this process id), otherwise after `SESSION_LOCK_STALE_MS` (default 30 s) without a heartbeat. The lock is checked around every write (a missing lock is re-checked once, so a takeover race cannot fool a live holder); `SESSION_LOCK_STALE_MS` ranges from 10 s to 10 minutes.
- Fail-stop (US-0018): when a log write or `fdatasync` fails or the session lock is lost, the server records nothing more, refuses all input, sends every client an unlogged notice, logs one `FATAL` line and exits non-zero after about 2 s for a supervisor to restart it; the restart resumes from the log (the event whose write failed may be on disk although no client saw it). Restores replay in linear time. A crash during the restart's own completion is completed by the next restart (the alert says what it completes, never that it is done). Docker Compose restarts the runtime on failure, at most 5 times (`restart: on-failure:5`); `./run.sh --dev` does not restart. A lock lost while the server starts also ends in FATAL, and a stuck shutdown is cut after 5 s. A log left under two names by an interrupted rotation is finished on the next start; a log the server creates itself is never refused for its owner (mounts that remap owners).
- `pnpm demo --resume` (US-0018): the resume room, ten opt-in checks F-34 to F-43 (39 with the default run): a crash mid-scene and the restart (same state, paused, the remaining scene time, nothing overdue on `/resume`, the pending line answered once, players' visible history), the scenario-mismatch and corrupt-log refusals, the fresh and ended rotations, the lock, and logs cut mid-operation. CI runs it.
- Game Master release suggestions (US-0034): a hidden fact may have an optional `earned_when` condition in its role file (`earned_when: { 1: <condition> }`, keyed by the fact's 1-based number; trimmed, 1 to 500 characters; the validator refuses a number the character has no fact for). A scenario without it behaves exactly as before (same Game Master calls and events, same scenario hash). On its usual cadence, after the exit conditions, the Game Master judges the pending conditions of the AI characters in the current scene (at most 2 per round, least recently judged first, none in a round whose exit verdict is true) through the same nonce-signed path (fresh nonce, strict parser, one re-ask); the prompt holds the condition, the character and the fact number, never the fact text. A true verdict appends the facilitator-only event `gm.fact_earned {sceneId, roleId, fact, reasoning, via}` (no fact text) once per fact per session, also across a restart (rebuilt from the log as `state.factsEarned`); the terminal client shows it as `[alert] Game Master suggests releasing hidden fact #1 of cfo (...): type /release cfo 1 to release it` and `/hidden` marks the fact `[suggested by the Game Master]`. Nothing is released by a suggestion. Players never receive the event and their snapshot carries no suggestion state. A false verdict records nothing; no usable verdict gives a facilitator-only info alert. Opt-in `GM_AUTO_RELEASE=1` (default 0, validated, a startup warning) lets the Game Master release the fact itself: `gm.fact_earned` then has `autoRelease: true` and is followed by the facilitator-only `npc.updated`; a crash between the two appends is completed on resume (new repair `gm_release`). The extended showcase gives the CFO's fact 1 a condition; `showcase.yaml` scripts the mock verdicts per character and fact (`mock.gm_earned`, validated against the scenario and the Game Master rounds): a no-suggestion verdict and the suggestion in scene 4, before the facilitator's scripted release in scene 5; the mock showcase honours `GM_AUTO_RELEASE=1` end to end. Duplicate `earned_when` keys that name the same fact (`1` and `"1"`) are refused at load; an earned check's model-failure alert names the fact by role and number. Narration, transcript and `--json` (`showcase.gm.suggestions`) show it by role and number only. Checks S-04, S-06 and S-07 were extended (no new check: 29, 14, 15 and 32 stay).
- Per-role player join codes (US-0033): when the server starts a new session it issues one random join code per player role (12 symbols of Crockford base32, shown as `XXXX-XXXX-XXXX`) and prints them once on its standard output (never in its log lines, errors, alerts, events or any client's messages); a player `join` must carry its role's `joinCode`. Only a salted SHA-256 of each code is kept, in memory and in `data/sessions/<id>.codes.json` (mode `0600`, never in the event log), compared in constant time. A missing or wrong code, an unknown or AI-played role and an unknown session all get the same generic `unauthorized` (it never says whether a role exists or is taken), the connection is closed (1008) and the address is charged in the failed-login throttle shared with the facilitator token. A restart of a session that has started keeps the codes that were handed out (they are not shown again); every other start issues and shows new ones (a restart before `/start`, `SESSION_START=fresh`, a restart after an ended session, a log moved aside by hand), and a start that fails before showing new codes withdraws them; a typed O counts as 0 and I or L as 1, non-ASCII input never matches; player typos share the per-address failed-login limit (behind NAT or Docker Desktop, a few typos can block that address for 60 s, the facilitator's handshake included); moving the codes file aside and restarting issues new codes for a running session; an unreadable codes file stops the start without changing anything. The facilitator token stays separate and a live rejoin with the reconnect token needs no code. The terminal client takes the code from `JOIN_CODE`, `--code-file <path>` or a hidden prompt (there is no `--code` argument) and tells a refused player to check the join code. `pnpm demo --url` reads the target's codes from `JOIN_CODES=role=code,...`; every demo server (main, side room, security and resume rooms) requires codes, and the existing checks were extended (F-01, F-02, F-22, F-24, F-28, F-37, F-40, F-41) with the check counts unchanged.
- Replay-from-seq on rejoin (US-0013): `join` and `join_facilitator` take an optional `lastSeq`; the `joined` reply then carries `replay: { afterSeq, toSeq, events, complete }` and is followed at once by the events after `lastSeq` that the role may see (the injects and whispers it missed included), filtered by the same default-deny rule as live events, before any live event: nothing is lost or repeated between the replay and the live stream. The engine keeps the last 4096 events in memory (refilled from the log on resume, so a client may rejoin with its seq after a restart); one rejoin replays at most 1000 events and 256 KiB, and never more than fits beside its snapshot in the 1 MiB per-client send buffer, otherwise `complete: false` and no events (the snapshot is the fallback). A `lastSeq` that is not a whole number is `bad_message`; one past the log is `bad_message` after the join is authorised; a refused join gets only its refusal. Without `lastSeq` a join behaves as before. The terminal client takes `--last-seq <n>`, prints the value to rejoin with when the connection drops (correct also when it drops in the middle of a replay), names a hidden fact released while it was away (facilitator), and drops a duplicate event. `gm.fact_earned` (US-0034) is facilitator-only in the replay as it is live. Demo checks F-02, F-20, F-22, F-25, F-34 and F-37 were extended (counts unchanged: 29, 42, 14).
- `pnpm demo` live evidence (US-0023): the 29-check run counts the AI character replies that were the persona's canned fallback line and shows the count in the narration, in check F-08's evidence and in a new `liveEvidence` section of the JSON report (`npcReplies`, `fallbackReplies`, `byCharacter`, `alerts`, `warnings`); a mock run reports 0 and keeps its check counts (29, 42, 14, 15). Each canned reply is labelled, and the facilitator alert behind it (sanitized, with its reason) is printed next to it; an end-of-run "Run summary" lists real against canned replies, the alerts and the join-code and replay features exercised.
- `--max-fallbacks <n>` now also works for the 29-check run (no `--showcase` needed): check F-08 fails when more than n replies were canned lines; without it the count is a warning. A bad value exits 2.
- Alert text in the demo's output, JSON report and Markdown transcript (the 29-check run and the showcase) is sanitized (US-0023): control characters become `·` and invisible ones are removed; configured secrets, join codes in every spelling the server accepts (any case, spaces or hyphens, O/0 and I/L/1 folded), Bearer values (also doubly escaped), key-shaped and long opaque strings (model ids, request ids and URLs stay readable) and hidden-fact text (also a start of one cut off by a provider snippet) (any case, width form or invisible-character disguise) become `[redacted]`; the text is clipped to 300 characters. An alert is tied to a reply only when it caused that reply; otherwise it is listed as not tied to any reply.
- Friday starter calibration probes (EPIC-0005, US-0035): eight handwritten probes in `scenarios/friday-escalation/calibration/` (discovery levels 1 to 4, negotiation levels 1 and 4, a listening and a negotiation contrast pair; 4 tune, 4 holdout) that validate against the scenario's rubrics; they are run by `pnpm calibrate` (below); probe drafting and approval came with US-0037 (below), the calibration stamp on reports does not exist yet.
- `pnpm calibrate` (EPIC-0005, US-0036): runs a scenario's calibration probes through the real evaluator with the primary judge (the evaluator settings; `MODEL_PROVIDER=mock` is refused) and an optional second judge (`--judge label,model[,baseUrl]`, OpenAI-compatible, scored blind and compared); prints the planned model-call count first; reports agreement (exact and within one), bias (overall and by expected level), contrast ordering and spread, not-observed precision and recall, usability and, with `--repeat`, stability, split by criterion, tune/holdout, source and drafter, with thin-set and same-model-family (self-agreement) warnings and a PASS/WARN/FAIL label per judge; writes `calibration-report.md` and `calibration.json` to a new directory under `data/calibration/<scenario-id>/` (git-ignored, never overwritten) and one summary file per judge (created or replaced only by a complete run: all probes, all criteria, no failure or abort, enough usable answers; it records exact agreement, bias, contrast ordering with the number of contrast probes, and usable answers); `--only`, `--criteria all|probe`, `--json -|<file>`, and `--strict` (exit 1 on any FAIL; exit 1 also when the results cannot be written, 2 for usage or input errors). A judge that is down or answers garbage is recorded as unusable and the other judge still runs; partial results are written, also after Ctrl-C. Prompt variants other than `v1` and the calibration stamp on evaluation reports are not there yet (probe drafting and approval: US-0037, below).

### Security

- Provider secrets (`ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`, `LOCAL_API_KEY`) are never logged or put in URLs or error messages; the startup log shows a fixed provider label and a yes/no for "custom endpoint" only (no host or path), and the scenario-dir log line was removed. This addresses the CodeQL `js/clear-text-logging` alert on the provider log line in `services/runtime/src/main.ts`.
- Endpoint URLs (`ANTHROPIC_BASE_URL`, `OPENROUTER_BASE_URL`, `LOCAL_BASE_URL`) are validated at startup: userinfo, query strings and fragments are rejected, hosted endpoints must use https (plain http only on localhost), and errors name the variable without echoing the value. The OpenAI-compatible client and a custom Anthropic endpoint refuse redirects so credentials are never forwarded (the default Anthropic path is unchanged), caps error and JSON bodies, and truncates and sanitizes upstream error text.
- Facilitator access can require a token, connections and message rates are capped, browser origins are refused unless allowed, and frames are limited to 16 KiB (US-0017); with no token the server stays open and warns at startup. No TLS is still unprotected (player roles have join codes since US-0033): see `docs/THREAT_MODEL.md`.
- Players only receive events they are allowed to see (default-deny filter); other participants' ids, NPC goals, whispers and private facts are never sent to them.
- NPC and Game Master prompts never contain rubrics, other roles' private material or participant display names; the Game Master frames participant text as data so one participant cannot forge another's line.
- The terminal client sanitizes all server-supplied text so control or escape sequences from other participants or the model cannot manipulate a terminal.
- A role can only be taken over by a client presenting that role's reconnect token.
- A Game Master release suggestion (US-0034) cannot be forged from the dialogue: only a verdict carrying the evaluation's nonce counts, the role and fact number come from the scenario, the event is written only by the engine's Game Master path (no client message can create it) and is denied to players; the fact text never enters the Game Master prompt. `GM_AUTO_RELEASE` is off by default because a participant who persuades the model would release a fact without the facilitator.
- Live-model tests are opt-in only (`RUN_LIVE_MODEL_TESTS=1` plus an API key); the default test run never reaches the network.

### Known limitations

- Without `FACILITATOR_TOKEN` any client that can reach the server can join as facilitator; with it, facilitator access is protected but there is no TLS (clear text `ws://`; use a TLS reverse proxy); player roles are protected by their join codes (US-0033), but whoever is given a code can play that role. - A resumed session keeps no role claims (a role is claimed again with its join code). Injects and whispers are re-sent only to a client that rejoins with its last-seen seq, from the last 4096 events and at most 1000 events or 256 KiB per rejoin (US-0013); the terminal client does not reconnect by itself.
- One session per server process; text only (no voice, web or Teams client); no scoring yet.
