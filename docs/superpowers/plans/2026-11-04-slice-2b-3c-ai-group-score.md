# EPIC-0002 Slice 2b-3c: AI Group-Score Option and Evaluator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A facilitator chooses, until the start, whether AI players count toward group scores (default on, recorded in `session.started`), and the evaluator reads the AI roles and the option from the session log: AI roles never get an individual evaluation, report, model call or self-assessment; the group rubric uses AI lines as team evidence labelled AI (on) or as context only (off); every quote from an AI line is labelled in every report, export and review view; reports of sessions with AI players carry the calibration-stamp note; sessions without AI roles produce byte-identical evaluator requests and reports.

**Architecture:** PR 1 first records, on the current `develop`, a golden fixture of the evaluator and review outputs for sessions without AI roles, then carries the option end to end with no evaluator change: `session.started.includeInGroup` (`@acr/events`, still format 3), the engine and restore, the AI-role record (v2 only when the option is off), `setAiRoles(roles, includeInGroup?)`, both IPC copies (`set_ai_roles.includeInGroup`, `ready.includeInGroup`, `ready.includeInGroupReset`), the supervisor's in-memory option and every re-send path, the control and BFF routes, readiness, and a checkbox in the console. PR 2 changes the evaluator (`services/runtime/src/evaluator/`): a new `ai-players.ts` reads AI roles from the log fold and the option from `session.started`; the transcript labels AI players; `evaluateSession` skips them individually and switches the group prompt and verifier; reports, the index, the stamp, `verify.ts` and the review tool (`review/`) label and list them. PR 2 ends with the independent review AC-0326 requires.

**Tech Stack:** TypeScript, Node 22, zod 4, Next.js 16.4.1, React 19.3.0, vitest 5.0.3, Playwright 1.64.0 with @axe-core/playwright 4.13.0. No new dependencies.

## Rulings

- **C1 Two PRs, plumbing first.** PR 1 (`feature/EPIC-0002-US-0061-group-score-option`) carries the option from the UI to `session.started` with no evaluator change; PR 2 (`feature/EPIC-0002-US-0061-ai-evaluator`) is the evaluator, review tool and stamp, reviewed independently; since the evaluator change is the risky part and AC-0326 wants its own review, it must not share a diff with UI plumbing. Costs: an unreleased window where the option is recorded but not yet read.
- **C2 Absent in a request keeps; absent in a record means on.** A 3b-style role switch that sends only `roles` must never reset an "off" option; a log or file from an older build has no field and means on (obligation 9). The console always sends both fields.
- **C3 `session.started.includeInGroup` is written, explicitly true or false, only when `aiRoles` is non-empty.** Logs without AI roles are unchanged (format 2); format stays 3. Restore refuses (`invalid_log`) a non-boolean value, or the field in a log without `aiRoles` or below format 3.
- **C4 The AI-role file stays v1 while the option is on.** `{ v: 2, sessionId, scenarioSha256, roles, includeInGroup: false }` is written only when off, so a rollback to 3b reads every default lobby; v1 reads as on. Costs: a rollback to 3b refuses a lobby whose option is off ("cannot use the AI-role file", move it aside): documented in `docs/ROLLBACK.md`.
- **C5 An option-only change is a real change.** `setAiRoles` compares roles AND option: an option-only change persists the seats (AI-role file), returns `[]`, issues no code, kicks nobody, re-sends no roster. It is refused after the start (`started`) like a role change; the notice check stays roles-only (an option without AI roles is harmless).
- **C6 The option travels with every re-send.** `ready.includeInGroup: false` (lobby file or resumed log) and `ready.includeInGroupReset: false` (the lobby file BUG-0021's fresh-codes path dropped) are sent only when off; the supervisor keeps `Live.includeInGroup` and `afterCodedLaunch` re-sends roles and option together, with the in-memory pair winning when it has roles (BUG-0021 rule).
- **C7 Players never get the option.** `includeInGroup` is excluded from `STARTED_FOR_PLAYERS` and not copied to the console timeline; the console learns it from the control service's session info (`GET /sessions/:id` and the readiness answer).
- **C8 Checkbox, no dialog.** The checkbox shows on readiness (idle) and the created-session panel only while at least one role is AI, with no confirmation (it is reversible until the start and changes no seat); after the start readiness shows the read-only line.
- **C9 The evaluator reads the log only and fails closed.** AI roles = `aiRolesOfStarted(started)` (today's `foldAiRoles`, exported from `@acr/events`), never `reduce` (which throws when the first seq is not 1). When `aiRoles` is present it must be an array of distinct strings, each a player in BOTH the scenario and the event's `roles`, in a log of format 3 or above; otherwise, and for `includeInGroup` without `aiRoles`, the evaluator refuses `EvaluatorInputError("the log's session.started.aiRoles is not a list of distinct player roles")` (exit 2), like the runtime's restore, because dropping a bad entry would score an AI seat as human. The option = `started.includeInGroup !== false`; a present non-boolean is an input error.
- **C10 AI players are labelled in the transcript in both settings.** `speaker: "ai_player"`, label `<id> (AI player)`, scene headers mark AI participants `<id> (AI player)`; AI-character lines are untouched.
- **C11 Off reuses the AI-character path.** The group verifier then allows only `speaker === "player"`, exactly how AI-character lines are kept out today, and the group prompt calls AI lines context only.
- **C12 On labels every AI quote.** The verifier allows `player` and `ai_player`; a verified quote from an AI line carries `ai: true` in `Evidence`, JSON evidence and notable moments, and Markdown prints ` (AI player)`; `verifyReportFiles` fails a group report with an unlabelled AI quote or an AI quote while off.
- **C13 A team score needs human speech.** In both settings the group needs at least `MIN_UTTERANCES` lines by human players; AI lines add evidence but never make a team scorable alone. Copy with AI roles: `insufficient evidence: the human players spoke N time(s)`; without, unchanged (Owner question 2).
- **C14 No individual path for AI roles.** No `ParticipantEval`, model call, `<role>.md/.json`, LO column or self-assessment; a log whose player roles are all AI is `EvaluatorInputError("every player role in this session is an AI player: there is no one to score")`.
- **C15 Participant prompt text unchanged; free text labelled by instruction.** Only the transcript lines differ in an AI session; the existing "all other speakers ... are context only" rule covers AI lines. The group prompt changes only when AI roles exist and then also tells the model to name an AI player as `<id> (AI player)` in rationales and talking points and, when off, never to credit their lines to the team. Prose is unverified: only quotes are guaranteed labelled (accepted risk R4).
- **C16 The stamp note covers both settings.** `StampState` gains `includesAi?: true`; one helper `reportStamp(evaluator, result)` feeds every report and the index; the note applies to any report of a session with AI roles, on or off (Owner question 1).
- **C17 The review tool lists AI roles from the group draft.** `GroupReport.ai_players = { roles, included_in_group }` (present only with AI roles) is validated by `loadDrafts`; the facilitator index adds a row per AI role reading `AI player, not scored`; self-assessment, export and `canView` for an AI role already refuse (no subject) and get tests, not code.
- **C18 Intent log, hints, prompt commands and bot alerts are never evidence.** The evaluator reads only `utterance` events of the session log; the intent log and hints are not in it (3b); tests assert both.
- **C19 Independent review.** A fresh reviewer on the most capable model, given the PR 2 diff, the spec sections and a checklist, with read-only access to the repository at HEAD (Task 16, before Task 17, in addition to the usual whole-branch review); its full findings go into the PR body; the controller fixes every Critical and Important finding with a failing test first; the owner rules on any finding the controller rejects; AC-0326 is ticked only after the fixes are re-reviewed.
- **C20 Ids.** PR 1: TC-0114 (AC-0323). PR 2: AC-0364, TC-0115 to TC-0120. TASK-0090 (reserved) covers both PRs; no new TASK. AC-0321 and AC-0322 stay open with notes (2c parts); US-0061 Done after PR 2; US-0060 stays In Progress.
