> **Revision 2 (2026-11-09):** this revision folds in an independent Opus review of Revision 1 (sixteen findings plus corrections). Each finding was checked against the code and the installed binaries before editing; "Review responses (Revision 2)" near the end lists every finding with where it was applied or why it was rejected. The largest changes: the root scripts call `pnpm -s --filter @acr/voice-ops run voice-<cmd>` (a bare `pnpm --filter ... up` runs pnpm's built-in `update`, K13); the STT request path is in whisper-server's argument list because 1.9.5 has no other way to set it, so it guards against browser-origin and DNS-rebinding access only (K14); whisper-server's stdout is discarded (it may print transcripts); Task 7's step order, repair mode and "already running" rule are rewritten; the real environment overriding `.env` is refused; K5 gives the per-address caps that apply when clients collapse to one address; a crash-looping LiveKit spends the budget; browsers rejoin by the person's own click after an outage (automatic rejoin is A3); a new **Independent review B2** follows batch 3.

**Goal:** One command, `pnpm voice:up`, brings up the voice infrastructure on the pilot laptop (a hardened native whisper-server on loopback, then LiveKit and the TLS proxy from `deploy/compose`) with real LiveKit keys generated into `.env` only when absent; `pnpm voice:check` reports whether everything a voice session needs is in place without printing a secret; `pnpm voice:down` stops everything `voice:up` started; the web server is loopback-only behind the proxy; a LiveKit outage no longer turns voice off for the rest of a session; and the owner has a runbook with the room-test script. Voice stays dark behind `VOICE_ENABLED=0`.

**Architecture:** A new workspace package `services/voice-ops` (`@acr/voice-ops`, TypeScript, no runtime dependency beyond `node:` built-ins and the workspace `@acr/adapters`) holds the three commands as small modules behind injected seams (command runner, detached spawn, file system paths, network and DNS lookups, clock, timers), so CI tests every decision without Docker, LiveKit or Whisper; the root `package.json` gains `voice:up`, `voice:down`, `voice:check` and `voice:timings` scripts of the form `pnpm -s --filter @acr/voice-ops run voice-up` (the package's own scripts are `voice-up`, `voice-down`, `voice-check`, `voice-timings`, and the root scripts say `run` explicitly: the existing `pnpm -s --filter <pkg> <script>` style would turn `up` into pnpm's built-in `update`, K13). `deploy/compose/voice.yml` adds a `livekit` service (always) and a `caddy` service (profile `lan`) under a fixed project name, each pinned by digest, LiveKit with its keys only from a private env file in the voice state directory and its API on `127.0.0.1` only. Control's `VoiceHost` stops counting a worker exit as a fault when the exit is a LiveKit loss and control's own probe of `LIVEKIT_HOST` finds LiveKit unreachable: voice is then "unavailable" (not "off"), control probes on a capped backoff (2 s doubling to 30 s) and restarts the worker when LiveKit answers, with one facilitator alert per outage and one on recovery; every other exit still spends the five-try budget, and so does an outage that starts again within `RESTART_STABLE_MS` of a recovery (a crash-looping LiveKit). Browsers do not rejoin by themselves after an outage (`voice-client.ts` has no retry loop): the recovery alert and the runbook tell participants to press "Join with voice" again; automatic rejoin is A3.

**Tech Stack:** TypeScript, pnpm workspaces, Node 22 (`node:child_process` `execFile`/`spawn` without a shell, `node:net`, `node:dns`, `node:tls`, `node:crypto` `X509Certificate` and `randomBytes`, `fs.statfs`, `node:util` `parseEnv`, global `fetch`), Vitest, Playwright 1.64 (one bind test), Docker Compose 2.24.0 or newer (the long-form `env_file` with `required: false`; installed: Docker 29.8.2, Compose v5.5.0, active Docker context **OrbStack** on a local unix socket, not Docker Desktop; not run by this plan), whisper.cpp `whisper-server` 1.9.5 (Homebrew), images `livekit/livekit-server` (tag `v1.13.11`, D1) and `caddy` (version chosen in Task 0). **No new npm dependency.** The optional DNS-challenge path (Task 13) needs a custom Caddy build with one DNS provider module: a new dependency, built only after the owner chooses it.

## Restart budget: the decision

Read `services/control/src/voice/voice-host.ts:160-210,389-404`, `restart.ts` and the A1b batch 4 notes (D13 to D22). **Chosen design (Tasks 10 and 11):**

| Worker exit | LiveKit ingest and a probe | Probe of `LIVEKIT_HOST` | Effect |
| --- | --- | --- | --- |
| code 3 (`EXIT_LIVEKIT_LOST`) | yes | no HTTP answer within 2 s | **Outage.** Not counted (`failures` unchanged, neither raised nor reset). `mediaLost = true`; `voice_availability { available: false, off: false }` (already sent at the exit, as today); ONE `livekit_lost` alert (closes an open voice turn like `worker_restarting`; it goes out when the probe has answered, so an open voice turn closes up to 2 s later than with today's immediate `worker_restarting`). Control probes again after `livekitRetryDelay(n)` = min(30 000, 2000 x 2^(n-1)) ms: 2, 4, 8, 16, 30, 30, ... s; no worker runs meanwhile. When a probe answers: `mediaLost = false`, ONE `livekit_recovered` alert (info: "The LiveKit media server answers again; voice input is restarting. Participants who lost voice press Join with voice again."), a new worker is spawned (not counted), and `mediaUnstable = true` until that worker has been `worker_ready` for `RESTART_STABLE_MS`; availability follows its `worker_ready` as today. |
| code 3 while `mediaUnstable` (LiveKit died again within `RESTART_STABLE_MS` of a recovery) | yes | no HTTP answer within 2 s | **A crash-looping LiveKit.** Counted once (`failures += 1`, as `workerFailed` counts); past `RESTART_TRIES` it is `voiceOff` as today; otherwise the same outage wait as above (one `livekit_lost`, probe schedule from 2 s, no backoff spawn). So a LiveKit that keeps dying right after each recovery reaches voice off through the five-try budget instead of cycling lost/recovered forever. |
| code 3 | yes | any HTTP answer, or the probe rejects | Counted, exactly as today (`workerFailed`). |
| code 3 | no (file ingest, or no LiveKit) | — | Counted. |
| 0, 1, 2, `null` (signal) | any | not probed | Counted. |

Kept: a spawn that throws counts; `voiceOff`, an ended session and control's shutdown stop everything (pending probe timers are cancelled and a late probe answer is ignored); `attach` spawns nothing while `mediaLost` or a probe is pending and tells the new runtime `available: false`; `available` is unchanged (it already needs a ready worker, and no worker runs during an outage, so a `!mediaLost` term could never decide it: Revision 2 drops it), and pages say "Voice is not available right now. Use the text box." for the whole outage without flapping; `mediaLost` gates only `attach` and spawning. After the recovery, participants whose LiveKit connection dropped press "Join with voice" again (no automatic page rejoin in A1c, K15). Known noise during an outage: each seat room's periodic token sweep (`SWEEP_INTERVAL_MS` 20 s, `services/control/src/voice/tokens.ts:14`) logs a failed admin call every 20 s, and A1b's admin calls carry no timeout of their own (filed as a follow-up, see "Review responses"). Why a probe and not the exit code alone: R4 and K7. Why no cap on outage retries: an outage costs nothing but a loopback GET every 30 s and the session keeps running by text; a misconfigured LiveKit that answers HTTP but refuses every room still reaches voice off within the five-try budget. Why 2 s first: a LiveKit container restart takes seconds, so voice comes back about as fast as before for short blips.

## Global Constraints

- Every A1a and A1b invariant holds: no change to the session log format, `LOG_FORMAT`, the consent file, the voice record or any event; `VOICE_ENABLED` defaults to `0` and **`voice-ops` never sets it, `CONSENT_NOTICE_VERSION` or `SPEECH_INGEST`** (it prints what an operator must set, and that voice stays pre-production only); the privacy invariant (A1b Global Constraints) is unchanged.
- **Secrets are never printed, logged or put in an argument list:** `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, the `STT_URL` request path, `VOICE_DNS_API_TOKEN`, any `.env` value. **One exception (K14):** the request path is in `whisperArgs`, because whisper-server 1.9.5 has no other way to set it; it is therefore readable by local processes (`ps`) and guards only against browser-origin and DNS-rebinding requests. `voice-ops` output lines are fixed sentences plus non-secret facts (mode, hostname, ports, model label, days to expiry, versions, check levels). A test scans every command's output, every argument list given to the command runner or the detached spawn **except `whisperArgs`**, and every environment passed to a child, for the secrets of its fixture `.env`, and asserts the request path appears in `whisperArgs` only.
- **`.env` writes:** only names that are absent are added, as one appended block; an existing value is never changed; the file is read through one descriptor opened with `O_NOFOLLOW`, must be a regular file owned by the user with no group or other permission bits, and is replaced atomically (an `O_EXCL` 0600 temp in the same directory, fsync; before the rename the read descriptor's `dev`, `ino`, `size` and `mtimeMs` are compared with an `lstat` of the path, and any change aborts with the file left alone; rename, directory fsync); a symlink, a missing file (the sentence says to run `./run.sh` first, which creates `.env` with the facilitator token), a group- or world-readable file (the sentence says `chmod 600 .env`), a `.env` tracked by git, a half key pair, an empty assignment of a managed name and the public development keys (`devkey` / `secret`, any case) are refused with the file unchanged byte for byte. Concurrent `voice:up`/`voice:down` runs are excluded by an `O_EXCL` `<VOICE_STATE_DIR>/lock` holding the pid (a lock whose pid is dead is taken over).
- **One view of the managed values (finding 7):** control merges `.env` under the real environment (`services/control/src/config.ts:46-58`, the real environment wins). `voice:up` refuses with a fixed sentence when the real environment sets any managed name (`MANAGED_NAMES`: `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `STT_URL`) ("unset LIVEKIT_API_KEY in this shell: voice:up and control must read it from .env"), and `writeLiveKitEnv` and `whisperArgs` take their values from the same merged view (`loadRootEnv`) control uses, re-read after `ensureVoiceSecrets` wrote.
- **Generated values:** `LIVEKIT_API_KEY` = `API` + 24 hex (12 random bytes); `LIVEKIT_API_SECRET` = 64 hex (32 random bytes); the STT request path = `/` + 32 hex (16 random bytes); the STT port a value in 20000..32767 (below the macOS and Linux ephemeral ranges) from `randomBytes`, the first of up to 20 draws that `portFree` reports free; all from `crypto.randomBytes`. A hand-set `STT_URL` on `[::1]` is refused (whisper-server binds 127.0.0.1 only); its request path is the URL's pathname without a trailing slash, and an empty one or one under 16 characters is refused (`short_stt_path`, batch 2 review B F10: `--request-path` is always passed).
- **whisper-server is always started as** `whisper-server --host 127.0.0.1 --port <port> --request-path /<32 hex> -m <STT_MODEL_FILE> -sns --public <empty 0700 directory in the state dir> --tmp-dir <state dir>/tmp` and **never with `--convert`**; nothing calls `/load`. It runs with `cwd` = the state directory, an environment of exactly `PATH` and `HOME`, **stdout discarded** (it may print segment text, K16) and stderr appended to the private `whisper.log`.
- **LiveKit:** never `--dev`; keys only from `<VOICE_STATE_DIR>/livekit.env` (0600, `LIVEKIT_KEYS=<key>: <secret>`; long-form `env_file` with `required: false` so `compose down` works after a crash removed it), never `env_file: ../../.env`; API port `127.0.0.1:7880:7880`; `node_ip` = the LAN address in `lan` mode, `127.0.0.1` in `local` mode; media `7881/tcp` and `7882/udp` on that address only; `logging.level: error` (batch 2 review B F1; Revision 2 had `warn`); `security_opt: [no-new-privileges:true]` (F8); `restart: on-failure:5` (a crash restarts by itself, which is what the outage path waits for). Residual (K12): the keys are visible to `docker inspect` and `docker compose config` without `--quiet`.
- **Caddy (`lan` profile):** `admin off`, `servers { protocols h1 h2 }` (no HTTP/3: UDP 443 is not published), no access log (no `log` in a site) and a global `log default` that deletes `access_token`, `join_request` and `sid` from every logged request URI at level ERROR (batch 2 review B F1, UNVERIFIED until Task 15), no `trusted_proxies`, no `X-Forwarded-For` header directive, owner-supplied `tls <cert> <key>` (read-only mounts), the LiveKit site forwards `/rtc*` only with `header_up -Cookie`; ports on the LAN address only; `restart: on-failure:5`.
- **Images pinned by digest** (`image: name:tag@sha256:...`), the compose project name fixed to `scenecoach-voice`; compose is started with `up -d --no-build --wait --wait-timeout 60 --quiet-pull` (a service that exits at once fails the command instead of returning 0); Docker Compose 2.24.0 or newer and a **local** Docker endpoint only (`DOCKER_HOST` unset or `unix://`, and the current Docker context's endpoint `unix://` or `npipe://`; anything else is refused by `dockerProblem`, not `composeEnv`, so batch 3 calls `dockerProblem` before BOTH `up` and `down`: batch 2 review B F7); `voice:up` starts nothing it cannot stop: the state file is written before anything is started and updated right after each start; a failure after a start rolls back what was started.
- **State directory:** `VOICE_STATE_DIR` (absolute; default `<HOME>/.scenecoach/voice`, never inside the repository), mode 0700, owned by the user, not a symlink; files 0600: `state.json`, `lock`, `livekit.env`, `whisper.log` (whisper-server's stderr only); directories 0700: `public/` (empty), `tmp/`, `caddy-data/`, `caddy-config/` (batch 2 review B F9: Caddy's `/config`).
- No new npm dependency; `voice-ops` imports only `node:` built-ins and `@acr/adapters` (root index). No regular expression with a letters-digits-underscore class (id-rule guard, R13): hex, hostnames and addresses are checked character by character.
- Tests: no real-time sleeps and no absolute time assertions; injected `SetTimer`, clock, command runner, detached spawn, `fetch`, DNS lookup, `statfs`, network interfaces; private temp directories (`TMPDIR` set per file where a test lists temp files); real-process tests (`vi.setConfig({ testTimeout: 90_000, hookTimeout: 90_000 })`) use stub `whisper-server` and `docker` executables on `PATH` (`PATH` = a private stub directory, then `dirname(process.execPath)`, `/usr/bin`, `/bin`; each stub is copied into the private directory and `chmod 755` at test time, so the committed file's mode does not matter), and the repository root they act on is a private copy named by `VOICE_OPS_REPO_ROOT` (absolute, must hold `pnpm-workspace.yaml`; Task 7); Linux-safe (`stat` with no `-f`, no `/proc`).
