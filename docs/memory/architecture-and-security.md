# Architecture and security conventions

## Shape of the system (monorepo: `packages/events`, `packages/script`, `packages/adapters`, `services/runtime`, `scenarios/`)
- **Event-sourced.** Session state is always a projection of an append-only JSONL log through the pure reducer (`packages/events/src/state.ts`). `reduceReplay` is an in-place twin used only by restore (marked `@internal`); a property test proves it equals `reduce`.
- **Engine** (`services/runtime/src/engine`): mutex-serialised operations; the log is the source of truth. **Host + WebSocket server** (`host/`): default-deny per-role event filtering (`viewFor`, `snapshotFor`, `filterFor`); a new event type is invisible to players until explicitly allowed.
- **Replay-from-seq (US-0013):** `join`/`join_facilitator` take optional `lastSeq`; `joined.replay {afterSeq,toSeq,events,complete}` then the event frames. Source: `engine/recent-events.ts` ring (4096, pushed in `emit` after `reduce`, before subscribers; rebuilt in `restore`), filter: `SessionHost.replayFor` = the same `viewFor`; caps 1000 events / 256 KiB, else `complete:false` and no events. Ordering rests on the join handler doing replay, snapshot and subscribe with NO await in between: never add one there. Beyond-head is `bad_message` only after authorisation.
- **Agents** (`agents/`): `NpcAgent` (first-token and total deadlines, canned `fallback_line` marked on the event, repetition guard, `<silent/>` turns), `GameMaster` (evaluates exit conditions every N utterances, one bounded re-ask, `gm.no_verdict`), prompts built by pure functions.
- **Scenario fields for AI characters:** `persona, goals, knowledge, hidden[], guardrails, fallback_line, voice, seniority (1..5), responds_with[], only_you_say[], defer_to[], defers_text`. Role and scene ids may not be `__proto__`, `constructor`, `prototype` or `facilitator`.

## Game Master verdicts (a `true` ends a scene: the dangerous direction)
Each evaluation carries a fresh 16-hex nonce in the SYSTEM prompt only. Only a verdict object with `"id": <nonce>` counts (case and surrounding whitespace tolerated). Quoted text, an echo after the answer, nested objects, duplicate keys, arrays, truncated replies and conflicting verdicts are never accepted. Each model call has its own abort signal linked to the deadline.
US-0019: a Game Master prompt holds the latest `GM_TRANSCRIPT_WINDOW` (40) scene lines, widened per condition to every line since its last ANSWERED prompt (`coveredSeq`, cap 500 with a facilitator alert), plus the first 2 scene lines and each AI character's last 2, each with the line before it (`selectGmLines`; `windowFor` is synchronous with the prompt build), `{"omitted": n}` records in place and a numbers-only system note; no summary. Residual risk (THREAT_MODEL): a player's objection flooded out by later lines. A round stops judging once an exit verdict is RECORDED true (`exitVerdictTrue`). NPC prompts: `stableNpcPrefix(role)` (instructions, persona, guardrails, voice) first, `cachePrefixChars` marks it, Anthropic puts the breakpoint there (never inside a surrogate pair); S-06 asserts one identical prefix per character. The shipped prefixes are about 420 to 520 tokens, likely below the minimum cacheable length: savings not measured.

## Hidden facts
`release_hidden {roleId, fact (1-based)}` records `facilitator.command` (no text) then the facilitator-only `npc.updated{released}`. A released fact appears only in that character's prompt, in `## What you may now share`. Players, other characters, the Game Master, generated players, the evaluator and every demo output never contain the text (except the owner saying it aloud later). S-06 judges prompts by time against the release seq. US-0034: an optional `earned_when: {<n>: condition}` per fact; the Game Master judges pending ones (characters in the scene, not suggested, not released) after the exit conditions through the same nonce path, its prompt never holds the fact; a true verdict appends the facilitator-only `gm.fact_earned` (no text) once per fact per session (`state.factsEarned`, rebuilt from the log). `GM_AUTO_RELEASE=1` (off by default) adds `autoRelease: true` plus the `npc.updated`; resume repair `gm_release` completes a cut one.

## Session log, resume and fail-stop
- Log format 2 since EPIC-0002 slice 2a (format 1 before): `session.started` carries the format and a SHA-256 of the loaded, schema-validated scenario, and in format 2 optional `consents`, `names` and `logIdentity` (a player's copy: own consent only, via an allowlist `STARTED_FOR_PLAYERS`). Formats 0 to 2 restore; an older runtime refuses 2 (docs/ROLLBACK.md). Auto-resume comes back PAUSED (`session.resumed`); downtime counts as paused time (`pausedMs`, `activeElapsedMs`; pause freezes the scene clock). Refused on corruption beyond a cut last line, a newer format or a scenario mismatch; `SESSION_START=fresh` moves the old log aside.
- Single-writer lock `<id>.lock` (O_EXCL/O_NOFOLLOW, heartbeat, stale takeover that pins the judged file descriptor). `fdatasync` per append, files 0600, directory 0700, directory fsync.
- **Fail-stop:** after any write, sync or lock failure the log is permanently broken and the engine halts; clients get an unlogged `log_failed` notice; the process exits 1 and a supervisor restarts it (compose `restart: on-failure:5`; `run.sh --dev` does not). An event may be on disk that no client saw: the log is the truth.
- A crash between the appends of one operation is completed on the next resume (tested at every event boundary).

## Evaluator (`services/runtime/src/evaluator`, rubrics in `scenarios/*/rubrics`)
BARS, four levels (1 Not yet demonstrated .. 4 Advanced) plus Not observed. A 3 or 4 needs a verified verbatim quote from that participant's own line (else capped at 2); confidence from distinct lines; learning-objective means with labels; no single overall grade. Reports are DRAFTS held for facilitator review; participants see each other's reports for now (prototype setting; isolation planned). The method text is printed in every report.

## Security conventions (all learned from review or CodeQL on this repo)
- Never stat/lstat/exists a path and then open or read it: open ONCE, `fstat` the descriptor, use `O_EXCL`/`O_NOFOLLOW` (CodeQL `js/file-system-race`, high; flagged six times).
- Open a log or data file with `O_NOFOLLOW` (and `O_APPEND|O_CREAT|O_WRONLY`) and read optional files by read-and-catch `ENOENT`, never `existsSync` then read (control service `spawn.ts`, `config.ts`). Build lists of missing settings from names only, never from `[name, value]` pairs (CodeQL `js/clear-text-logging`).
- Never log an environment-derived string (host, path, token, origin): log constants, ports and booleans (CodeQL `js/clear-text-logging`, high).
- `js/file-access-to-http` on `gm-eval --live` (repo-committed labelled cases to the model) is by design; it did not fail the CodeQL check.
- Own-property lookups for any client-supplied id; refuse prototype keys at load.
- Transcript Markdown: every model or participant line goes through `safeMd`; raw text is split on newlines BEFORE sanitising.
- Player join codes (US-0033): `engine/join-codes.ts` (12 Crockford base32 symbols, salted SHA-256 bound to the role, `timingSafeEqual`, dummy digest for roles without a code); hashes in `<id>.codes.json` written by `openSession({ joinCodes: true })` under the lock at startup only (kept ONLY on resume; empty/missing log, fresh and ended issue new ones; removed BEFORE a fresh/ended rotation; a malformed file refuses a resume; `discardIssuedCodes()` withdraws unseen codes on any bootstrap failure; stale `.tmp` swept under the lock; O->0, I/L->1, non-ASCII refused before upper-casing; unknown session verifies against `JoinCodes.none()`). Plain codes leave only through bootstrap's `showJoinCodes` (stdout), never `log`/`warn`. `startServer({ joinCodes })`: every refused player join is one generic `unauthorized`, closed and charged in the shared `AuthThrottle`; a live takeover still needs the reconnect token (and then no code). Unset `joinCodes` = open roles (tests only). Demo servers all require codes (`sys.joinCodes`, `playerJoin(ctx, ...)`); `--url` reads `JOIN_CODES`.
- Facilitator token: SHA-256 + `timingSafeEqual`, never logged; a refused connection is closed and its queued frames dropped; per-address failure throttle; open-by-default with a loud warning until a later release (fail-closed). Threat model: `docs/THREAT_MODEL.md`.

## Web client (EPIC-0002 slice 2a, US-0052..US-0056, US-0065)
- `apps/web` (Next 16.4.1 pinned (R16: older 16.x/15.x have advisories), `--webpack` for dev/build (R17: Turbopack cannot resolve the `./state.js` specifiers in `@acr/events`)). BFF logic is plain `Request -> Response` modules in `src/server/` (config, seal, envelope, guards, throttle, runtime-connection, stream-hub, sse, headers, handlers, routes); route files only re-export. `src/proxy.ts` is Next 16's middleware (per-request nonce CSP); its matcher EXCLUDES `/api` (otherwise Next buffers up to 10 MB of each POST body before the route's 8 KiB cap).
- Identity only from the sealed cookie `__Host-scenecoach` (AES-256-GCM, key id as AAD, `COOKIE_KEYS` newest first, `{sessionId, roleId, participantId, credential, logIdentity, expiresAt}`); never from a body (confused-deputy rule). Hub `send` allowlist: say, consent, withdraw_consent, leave.
- Runtime additions: `<id>.credentials.json` and `<id>.consent.json` (0600, same writer as codes; kept only when codes are kept); credential issued only on `issueCredential: true` (web), then the code no longer opens that role; close 4001 superseded; `leave` refused after the start (R13); start gate `seats_not_ready`; after the start only the consenting participant takes a seat (`consent_required`), seeded from `session.started` on resume (R14, `ConsentStore.adopt`, no version comparison: R15); roster frames from host memory (facilitator vs peers); `joined.scenes`, `joined.logIdentity`, `joined.consent`; failed logins per (address, scope) `player:<role>`, `player:*`, `cred:<role>`, `""` (facilitator).
- Browser state: `initPlayerView`/`applyPlayerEvent` (`packages/events/src/player-view.ts`), never the throwing shared reducer. Hub sends `reset` on incomplete replay, beyond-head `Last-Event-ID` or another log identity (and the route reissues the cookie).
- Address: the proxy must REPLACE `X-Forwarded-For` with one entry; BFF refuses lists/empty (400). `next start` fills an ABSENT header with the socket address (so: no proxy = per-socket keys but forgeable by the client; a proxy that does not set it = everyone shares the proxy's address); `unknown` only in unit tests. BFF JoinThrottle fails closed when saturated by blocks (R20).
- Known limits (THREAT_MODEL "Known limits of slice 2a"): lost cookie = no rejoin until US-0058; delayed-tab race; ack-less cookie clear on leave/withdraw; non-transient refusals loop as Reconnecting; a closed stream (401/403/406/503) can only say "reload, then ask your facilitator"; API lacks COOP/CORP; IPv6 not keyed by /64; concurrent requests pass BFF pre-checks.


## Control plane and facilitator console (EPIC-0002 slice 2b-1, US-0057..US-0059; built 2026-10-30 on three stacked local branches, not pushed)
- **Process model.** Browser -> BFF (`apps/web`) -> control service (`services/control`, 127.0.0.1, `x-service-token` = `LAUNCHER_TOKEN`) -> one runtime child per session via `fork()` + IPC. The browser never talks to the control service or a runtime. Facilitator tokens (64 hex, fresh per start) live only in memory in the control service and the BFF.
- **Managed mode** (`CONTROL_MANAGED=1`, implies `NO_DOTENV=1`; `SESSION_DATA_DIR` absolute, `<CONTROL_DATA_DIR>/sessions`): on an empty log the codes, seats and consent are KEPT (a terminal runtime discards them); an ended log is REFUSED (never rotated); a parent `disconnect` stops the runtime (hard-exit backstop for a hung stop). IPC up: `codes` (only when this start issued codes; a failed synchronous send aborts the start), `ready {port, logIdentity, status, modelLabel}`, `ended`. IPC down: parent-only `reissue {roleId}` -> `{reissued, roleId, code}`; no network route reissues.
- **Child environment** is an allowlist (`services/control/src/child-env.ts`): `PATH`, `NODE_*` (copies `NODE_OPTIONS`), provider keys and NPC/GM settings; `HOME`, `ALLOWED_ORIGINS`, `WS_MSG_RATE/BURST`, `WS_JOIN_TIMEOUT_MS` are NOT passed; `GM_TRACE_FILE` never. `LAUNCHER_TOKEN` and `FACILITATOR_SECRET` never reach a runtime.
- **Reissue order** (`host/reissue.ts`): write the new codes file first, then revoke the credential (withdraw consent before the start, `releaseForRebind` after it), persist seats, kick with close 4002 (`CLOSE_REISSUED`), `setCodes` in a `finally`, then the post-start alert. A failed seat persist restores the credential and consent in memory. A pre-start alert would wedge `engine.start` (`log_not_empty`), so none is appended before the start. Rebind marker: `REBIND_PENDING = "rebind-pending"` in `engine/consent.ts`; a client can never choose it as a participant id; it survives resume under any notice version. The console enables per-role Reissue while the session is idle OR running (rebind-specific confirmation text when running); Reissue all stays idle-only.
- **Control service**: `Supervisor` (create, restart, reissue, reissueAll, resumeAll, shutdown) over an injectable `ChildHandle` (`kill`, `forceKill`, exit/message callbacks); rollback awaits child exit (bounded by `graceMs`), force-kills, then deletes files and frees the slot (R9). `sessions.json` (`sessionId, scenarioId, status`, 0600, atomic writer local to the package: it must not import `@acr/runtime`, R7). Status `running|stopped|ended`; crash = `stopped`, restart is manual. Timeouts: create/restart/reissueAll up to `readyTimeoutMs + 2*graceMs` (BFF client uses 120 s, reads 5 s, R10).
- **BFF**: facilitator cookie `__Host-scenecoach-fac` (purpose bound into the AAD; epoch derived from `FACILITATOR_SECRET`); `Deps.launcher` + `runtime-lookup.ts` (dual mode: `LAUNCHER_URL` set -> per-session lookup, else `RUNTIME_URL`); facilitator sockets fetch `{port, token}` together, send no `X-Forwarded-For`, retry once with a fresh pair on a refused token; runtime close 4002 is terminal for the player stream. Readiness: `status` = runtime state (`idle|running|ended`), `launcherStatus` = control state (R1).
- Detail and accepted limits: `docs/THREAT_MODEL.md` ("Facilitator console and control service"), `docs/ARCHITECTURE.md` section 6, rollback in `docs/ROLLBACK.md`. No log-format change in 2b-1 (format 3 is 2b-3).

## Live console runtime protocol (EPIC-0002 slice 2b-2a, US-0059; PR 1 allowlisted copies merged as #65, PR 2 on `feature/EPIC-0002-US-0059-runtime-protocol`)
- **Player copies are allowlists** (`services/runtime/src/host/player-copies.ts`): the join snapshot, `facilitator.command`, `session.ended` and `session.started` a player gets are built key by key, never by spread, so a new field is denied to players until listed. `PlayerSnapshot = Omit<SessionState, "talk">` (`packages/events`); the facilitator's `joined.state` is the full `SessionState`. A new facilitator-only field goes on BOTH leak-scan lists (`hub.runtime.test.ts` and `apps/web/src/demo/web-demo.ts` W-07); both now include `"talk":` and a `by` marker.
- **`by`** (facilitator name) rides `command` and `end_now`: raw at most 200 UTF-16 units (`bad_message` over), cleaned to 60 code points (`cleanFacilitatorLabel`), recorded on `facilitator.command`, named in the `end_now` alert, never in a player frame. It is a label, not proof of identity.
- **Talk time**: `state.talk[roleId] = { words, lines }`, folded from `utterance` events (own keys; `__proto__` safe), facilitator only.
- **`end_now` append order** (one engine mutex run, `SessionEngine.endNow`): `scene.exited{facilitator_end}` (when a scene is current), the facilitator-only alert, then `session.ended{facilitator_end, message?}` LAST. Refused as `not_started` (idle), `starting` (an interrupted start) and `ended`; never auto-starts (unlike `command`). `SessionHost.endNow` cleans `by` and the message (`cleanClosingMessage`: strip hidden/bidi/control, trim, 300 code points, whitespace-only means none; over is `bad_message`), then stops the ticker and clears the pending answer.
- **Restore repair**: a log whose latest scene exit is `facilitator_end` with no `session.ended` is repaired on restore (`end_session` repair, reason `facilitator_end`): the session is ended with an alert, the closing message is lost. No LOG_FORMAT bump on purpose (a bump would make older builds refuse every new log); the rollback consequence is in `docs/ROLLBACK.md`.
- **BUG-0016, ended after ready**: `markResumed` runs before `main.ts` subscribes, so a repair that ends the session sent nothing. `main.ts` now checks `host.engine.state.status === "ended"` once after `ready` and sends `ended` (once-only flag shared with the live subscriber) and calls `endSeats()`; the control service's `awaitReady` records an `ended` that arrives right after `ready` (peeking at `raw.type`, no parse of other messages) and `goLive` applies it through the idempotent `onEnded`.
- **The closing message reaches only players connected at the end**; a later rejoin gets `session_ended` with no message.

## Live console channel and read-only live view (EPIC-0002 slice 2b-2b1, US-0059; PR 1 #69, PR 2 #70, PR 3 `feature/EPIC-0002-US-0059-console-live-view`)
- **Reserved keys and budget**: every BFF facilitator socket sends the reserved `X-Forwarded-For` value `scenecoach-console` (the bot key is `scenecoach-bot`, used from 2b-3b); neither is an address, so no player can claim them, and a stale-token block lands on the console key only. The runtime's per-key cap is 8; the BFF's `FacilitatorBudget` holds 4 live-tab slots and 3 short-socket slots per session (7 of 8). Total cap arithmetic `2H + B + 7 <= 32` is an open item for 2b-3b (control service should refuse more than 12 player roles at create; a reconnecting bot must never hold two sockets).
- **Channel finals** (console stream): `ended` (view kept), `stopped` (back to the lobby), `expired`, `busy`; non-final `reconnecting`; browser-side finals `closed` (EventSource gave up) and `lost` (gap resyncs used up). The shell `SessionConsole` alone shows `ui.final`, once.
- **Gap resync**: the browser folds with the shared `reduce` (console copies only; players keep `applyPlayerEvent`). A gap closes the source and reopens it without `Last-Event-ID`; the new stream joins from seq 0: a complete replay (usual) is forwarded with no `reset` and the next in-order event clears the gap; a `reset` comes only for a missing or incomplete replay. The old view stays until then. `MAX_GAP_RESYNCS = 3`, counted as consecutive: an in-order event after a resync resets the counter (R3); the fourth is `lost`.
- **Console copies allowlist rule** (`apps/web/src/server/facilitator-copies.ts`, `console-roster.ts`): fields are picked key by key at the top level of each state and event, never by spread; `consoleEvent` is an exhaustive `Record<EventType, copier>` so a new event type is a compile error; an event type the BFF does not know goes as its envelope only (keeps seq gap-free); hidden facts, NPC goals, knowledge, released text, participant ids, the log identity and the runtime's alert text never reach the page (`facilitator.alert` shows a fixed line per level).
- **Rendering**: untrusted text only as React text children, names in `<bdi>`, `by`/labels/whisper text isolated with U+2068..U+2069 only when they hold bidi controls, no `dangerouslySetInnerHTML` or inline style, polite live region with `aria-relevant="additions"`.

## Facilitator controls (EPIC-0002 slice 2b-2b2, US-0059; PR 1 #73, PR 2 #74, PR 3 `feature/EPIC-0002-US-0059-console-controls`)
- **`ref` and `ack`** (runtime `ws-server.ts`): optional on `command` and `end_now`, `/^[A-Za-z0-9-]{1,64}$/` (else `bad_message`). Success is `{ type: "ack", ref }` to the sender only, after the host call and its events; a refusal is the `error` frame with the `ref`. A `command` with a `ref` before the start is `not_started` (`starting` while a start is in flight) and never auto-starts; without a `ref` the terminal facilitator still auto-starts. A player never gets an ack or a ref.
- **Hub correlation** (`facilitator-hub.ts`): one pending command per channel (`command_pending`), a fresh `randomUUID()` ref, `COMMAND_TIMEOUT_MS` 10 s, answered by an ack or ref'd error, or a ref-less `rate_limited`/`bad_json`/`bad_message`; a late answer is dropped; a pending `end_now` answers ok on ANY forwarded `session.ended` (it arrives before the ack and ends the stream), any other pending command is then unconfirmed.
- **Command answers** (`COMMAND_ANSWERS`, BFF-written fixed copy): 200 `{ done: true }`; 409 `stale_scene`, `not_started`, `starting`, `ended`, `already_released`, `conflict` (unknown inject/role/fact, npc role), `no_channel`, `command_pending`; 429 `rate_limited`; 502 `command_failed`; 504 `command_unconfirmed`. The runtime's message text never reaches the page; `by` is the cookie's name (a body `by` is 400). The browser shows the BFF message as text and never retries a command (a retried whisper or inject would apply twice).
- **`characters` frame**: per AI character `roleId`, `goals`, and per hidden fact only `{ n, released }` (matched by exact text); goals are the only secret text on the console stream. Hidden-fact text sits in the hub's memory for that stream and leaves only through `POST .../facts { channel }` when the facilitator opens a list; `CharactersPanel` keeps it in state only while a list is open and drops it on close, channel change and unmount. Knowledge never leaves the BFF. Player streams never carry `characters`, goals, fact text, a ref or an ack.
- **Console controls** (`components/console/ConsoleControls.tsx` and siblings; copy in `lib/console-confirm.ts`): Pause/Resume and Set stance act at once; Move on, End session, Fire inject, Send whisper, Release fact and Remove open the one `ConfirmDialog` that names the subject and audience. `expectSceneId` is the scene shown when the confirmation opened; a stale one is 409 and nothing is applied. Controls are `disabled` unless live and running, `aria-disabled` while pending. Status/alert text is published after the dialog lifted `inert`. Remove is in `Readiness` (joined seats, idle session only) and shows the new code once.
- **Whisper to a web player** (BUG-0019): `applyPlayerEvent` appends a received `facilitator.command` whisper to `injects` as plain text (recipient only). It is not in the join snapshot (a reload loses it) and has no "private" label (owner decision of 2026-11-03: it gets a "private" label and survives a reload, as its own small change after 3a).
- **Open (progress.md Session 16; owner decision of 2026-11-03: focus after End session, a connection drop or a 409 on Remove moves to the final banner or the error message, `tabIndex` -1, a small console change after 3a):** focus fallback when a dialog opener is disabled by a dropped connection; whisper text not cleared after send; parked e2e Minors; a `CharactersPanel` unit-test gap.

## AI player roles: state, gate, labels (EPIC-0002 slice 2b-3a, US-0060; PR 1 #78, PR 2 #79, PR 3 `feature/EPIC-0002-US-0060-ai-role-labels`)
- **Record**: `session.started.aiRoles` (scenario order, present only when there are some); `LOG_FORMAT` 3 only for such a session (`logFormatFor`), every other session stays format 2; the runtime reads 0 to 3. `state.aiRoles` is folded from the log (only strings that are player roles, deduplicated); the player copy of `session.started` carries it. A lobby keeps its AI roles in `<id>.ai-roles.json` (fourth seat file, `0600`, no secret): kept by a managed restart of an empty log, removed with the codes (`settleSeats` before new credentials), rewritten from the log after the start. It is not bound to `credentials.logIdentity` (ruling).
- **`set_ai_roles` (parent-only IPC, answered `ai_roles_set` / `ai_roles_failed`)**: no `by`, no `includeInGroup`; strict schema, at most 256 roles, `parent-channel.ts` and control `protocol.ts` copies equal (drift test); four fixed refusal reasons, anything else maps to "the AI roles could not be changed". Refused when the start is in flight, after the start and after the end. One synchronous turn (no `await`), so a join, reissue or start cannot interleave. Every role whose flag changes gets a NEW code written first (A2), its credential is revoked and consent withdrawn, then the seat files persist (codes, credentials, consent, AI-role file); a crash between files leaves a role without a credential, never an AI seat with a human's credential. Socket close: 4004 `ai_filled` to a human switched to AI, 4002 back to human. `Supervisor.setAiRoles`/`aiRolesOf` exist with NO HTTP or BFF route (A1; a test pins 404).
- **Gate and seats**: the start gate needs holder and consent for each human role and a connected bot (no consent) for each AI role, `seats_not_ready` names humans then AI roles; AI seats skip consent and rebind, `joined` has no `consent`, `consent`/`withdraw_consent` from them are `forbidden`; the AI credential name is always `AI player`. A join whose cleaned name (NFKC, case, spacing, hidden characters folded) starts with `AI player` is refused as `bad_message` before authentication (not counted as a failed login), a bot's included: the 3b bot sends NO `displayName`. "Aiden Player" and "AI-player" stay allowed and unmarked. Roster: `ai: true` (absent otherwise) from `aiRoles`, never from a name.
- **Notice v2 is the default** (`CONSENT_NOTICE_VERSION` defaults to `v2`; `notice-v1.md` unchanged, SHA pinned by a test). On a restart onto a new version a lobby keeps seats and codes but its old-version consents are dropped on read; a started session keeps every consent in its file whatever the version (R15, so a participant who took a seat over after a reissue keeps theirs) and seeds roles with no file entry from its log (R14); a different participant still gets consent_required. Builds before this slice, and of PR 1 and PR 2, serve v1 again (docs/ROLLBACK.md). 3b obligations: refuse AI roles unless the active notice names them (v1 stays selectable today), and never show an adopted older-version consent as agreed to the new text (THREAT_MODEL items 11 and 12).

## Voice input, slice A1a (EPIC-0003, US-0070; branch `feature/EPIC-0003-US-0070-voice-pipeline`; dark behind `VOICE_ENABLED=0`)
- **Shape.** `services/speech` (`@acr/speech`, exports `./protocol` only; imports no runtime or control source) is a per-session worker forked by control's `VoiceHost` (`services/control/src/voice/`), no network listener: file ingest (`<SPEECH_INGEST_DIR>/<roleId>.wav`, 20 ms frames) -> `VoiceGate` -> per-track `TrackPipeline` (energy `Segmenter`, hangover 500, forced split 2500 at the quietest frame) -> `LimitedSpeechToText` (Whisper over loopback HTTP, or the fake script) -> noise `gate` (signal, never phrases) -> `normalise` (conservative: strips control/bidi/zero-width, collapses whitespace, drops "dollars" after "$11,000", cuts at 2000; never rewrites words) -> IPC. Lines of one track are delivered in segment order; a failed or empty one is `segment_failed` in its place.
- **Messages.** Worker -> control: `worker_ready {stt}`, `voice_line {segmentId, roleId, participantId, text, startMs, endMs}`, `speech_activity {roleId, active, silentMs?}`, `segment_failed {status: stt_failed|empty}`. Control -> worker: `voice_state {paused, ended, holders[]}`, `voice_line_result {seq | refused}`. Control -> runtime (parent channel, both copies drift-tested): `voice_line`, `speech_activity`, `voice_notice`, `voice_alert`. Runtime -> control: `ready.voice: true`, `voice_seats`, `voice_turn {open}`, `voice_choice` (dropped by control in A1a; A2 audits it), `voice_line_ack {seq}`, `voice_line_refused {code}`. The supervisor's `awaitReady` holds the first `voice_seats` (sent in the same turn as `ready`); control sends `voice_state` only after `worker_ready`; on a runtime exit it fails pending lines and sends an empty holder list (the worker is kept, C6).
- **Runtime gate.** `SessionHost.onVoiceUtterance(role, participant, text)` records with `channel: "voice"` only for the current human holder who chose voice, else `VoiceRefusedError` (`VOICE_REFUSALS`); `voiceStateOf` is `none | voice | text_only | off`; the voice record `<sessionId>.voice.json` binds each choice to a participant (never inherited; `forgetVoice` on reissue). Player socket: `voice_opt_in {noticeVersion}`, `voice_opt_out`, answers `{type: "voice", state}`, `joined.voice` (own seat only), `voice_notice {code}` (own socket only, 10 s per role and code).
- **Turn timer.** `VoiceTurnTracker` (`services/runtime/src/host/voice.ts`, injected `SetTimer`): arms `max(0, TURN_END_MS - silentMs)` when every recording track is silent; new speech cancels; a typed line ends the turn at once; pause and end clear it with no round; a turn that recorded no new line runs no round (`lastAnsweredVoiceSeq`); `voice_alert worker_down` ends an open turn at once (`voiceWorkerDown`) and a speaking track with no news for 12 s is forgotten (`VOICE_ACTIVITY_STALE_MS`). The round runs only after every voice line received so far is recorded (the host's `voiceChain`, C3), at most one waiting as before. `closedTurnEnds` (last seq of each closed turn) is in memory only and grows for the session.
- **Cadence by voice turn.** `gmUnits(sceneLines, closedTurnEnds)`: a typed or AI line counts 1, a closed voice turn 1, an open turn 0; lines from before a restart count 1 per run of consecutive voice lines; `GameMaster` options `units` and `hold` (no evaluation while a turn is open; `engine.tick` still runs); restore uses the same units. AI players: `BotHost.voiceTurn(sessionId, open)` -> `Bot.setVoiceTurn`: while open no wake is armed and only the last human line is deferred; on close it is observed once. The prompt reservation hold is separate.
- **Failure paths.** Worker exit while running: one `worker_down` alert, no restart in A1a (`workerLost`). STT failure: speaker notice plus alert; empty: nothing (`NOTICE_EMPTY_SEGMENTS = false`). Alerts are fixed sentences, at most one per code per 30 s, and only between the start and the end.

## Voice in the browser and LiveKit, slice A1b (EPIC-0003, US-0071; branch `feature/EPIC-0003-US-0071-voice-livekit-consent`; dark behind `VOICE_ENABLED=0`)
- **Seat rooms.** One LiveKit room per (session, human role), `v` + 32 random hex, in control's `VoiceTokens` memory (`services/control/src/voice/tokens.ts`), created at the first token for the seat, deleted at the session end. A shared room would leak who speaks (LiveKit signals participants and active speakers to everyone). Identity `<roleId>.g<8 hex>`, generation = HMAC-SHA256(per-session 32-byte key, `roleId\nparticipantId`); a reissue, a rebind and a control restart change it; the worker is `SPEECH.<8 hex>` (never a role). LiveKit code lives in `packages/adapters/src/livekit` behind the `@acr/adapters/livekit` subpath only (the root index never loads `livekit-server-sdk`; `lint:sdk` keeps it in control).
- **Tokens.** Control `POST /sessions/:id/voice-token` (service token) for the current holder with `voiceChosen`; participant grant microphone-only, no subscribe, 600 s; the worker asks per connect (`livekit_token_request` -> `livekit_join` or `livekit_join_refused`). BFF `POST /api/v1/voice/token`: same-origin first, cookie identity, 20 per 60 s per participant, returns `{ token, url, expiresAt }` only. Tokens only with keys AND `SPEECH_INGEST=livekit`.
- **Removal and sweep.** Stale identities are removed on a new holder, leave, withdraw, AI fill, opt-out, reissue/removal, voice off and the end; a plain disconnect (`voice_seats.open`) removes nothing. Every seat room is swept every 20 s while a session has rooms (a removed browser can reconnect with its valid token), one retry 2 s after a failure.
- **Ingest gating.** `recording = started && voice && !muted && !voiceUnavailable` (runtime `buildVoiceSeats`), plus not paused/ended in the worker's gate. `LiveKitIngest` (`services/speech/src/ingest/`) joins with auto-subscribe off, subscribes at most one microphone track per identity whose generation is current, re-frames to 320 samples, and tags every frame with its generation; `TrackPipeline` drops a frame whose generation is not the gate's (frames buffered after an unsubscribe survive in rtc-node). `livekit-room.ts` re-requests wanted subscriptions on `Reconnected` (D59) and ends a read never answered after 10 s (D60). rtc-node's logger is set `silent` by file path.
- **Restart, health, budget.** Control restarts a worker after 500..8000 ms, voice off after the 6th exit in a row (reset after 60 s ready); exit 3 (a lost room) counts like any exit, so a LiveKit outage of about 16 s turns voice off for the session. Whisper health every 5 s with two agreeing polls; control sends `voice_availability { available, off }` on every change and every runtime `ready`, applied before anything else and never on the rate-limited alert path. One STT budget of 2 across sessions in control (`stt-slots.ts`), leased for `STT_COLD_TIMEOUT_MS` + 5 s; an expired lease kills that worker.
- **Mute.** `voice_mute { muted }` in runtime memory only, accepted in every state of a human seat, cleared on release; the page also unpublishes the track (`unpublishTrack(track, true)`) and re-posts its mute after every fresh `joined`.
- **Headers.** `/session/<id>` only gets `microphone=(self)` and `connect-src 'self' <LiveKit origin> <https twin>` when `LIVEKIT_URL` is valid (built from `liveKitOrigin`, never the raw value); the static rule `"/((?!session/).*)"` covers everything else with `microphone=()`.
- **Console.** Facilitator roster entries gain `voice?` and `speaking?: true` (peers never); the voice alert sentences pass through the console copy by an exact allowlist pinned to `VOICE_ALERT_SENTENCES` (now in `services/runtime/src/host/voice.ts`). The speaking indicator re-broadcasts the facilitator roster on every speaking-set change (not coalesced).
- **Unchanged in A1b:** the voice turn logic and `closedTurnEnds` (still unbounded per session; `voiceWorkerDown` is only called more often), the log format, the consent file, the voice record.
